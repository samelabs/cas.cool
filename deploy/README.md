# Deployment Templates & Reverse Proxy Guide

This directory contains configuration templates for running `cascool` in production behind an Nginx reverse proxy.

## Files

- `nginx.conf.template`: Parameterized Nginx configuration template without hardcoded environment paths or secrets.
- `cas.cool.nginx.conf`: Reference instance configuration.

## Setup & Migration Instructions

1. **Copy Template:**
   ```bash
   cp deploy/nginx.conf.template /etc/nginx/sites-available/cascool.conf
   ```
2. **Substitute Environment Variables:**
   - `${DOMAIN}`: Your public production domain (e.g. `cas.cool`).
   - `${APP_DIR}`: Absolute directory where the application is deployed (e.g. `/var/www/cascool`).
   - `${SSL_CERT_PATH}`: Absolute path to your TLS certificate (`fullchain.pem`).
   - `${SSL_KEY_PATH}`: Absolute path to your TLS private key (`privkey.pem`).
   - `${UPSTREAM_PORT}`: The port the local Next.js server listens on (default: `3000`).

3. **Reverse Proxy Trust Boundary & Rate Limiting:**
   - The application relies on `X-Real-IP` and the last hop of `X-Forwarded-For` to enforce per-IP rate limiting on public and anonymous endpoints (`src/lib/rate-limit.ts` / `src/lib/api-auth.ts`).
   - Ensure Nginx sets:
     ```nginx
     proxy_set_header X-Real-IP $remote_addr;
     proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
     proxy_set_header X-Forwarded-Proto $scheme;
     ```
   - Do not allow untrusted incoming client headers to spoof `X-Real-IP`.

4. **Dynamic `/llms.txt` Route:**
   - In Next.js, `/llms.txt` is dynamically generated by `src/app/llms.txt/route.ts` to reflect the database-backed `SiteConfig` row.
   - Do NOT alias `/llms.txt` to a static file in Nginx; let requests proxy to Next.js.

5. **Media Storage Mapping (`/uploads/`):**
   - The application resolves its media roots from the server runtime env (`UPLOAD_DIR` for public media, `PRIVATE_UPLOAD_DIR` for private verification attachments — `src/lib/media-storage.ts`); both are absolute, disjoint paths and may live on shared storage outside the app directory.
   - The Nginx `/uploads/` alias MUST point at the **same physical storage** `UPLOAD_DIR` resolves to (follow symlinks when comparing). A mismatch makes the app accept references to files the proxy cannot serve.
   - `PRIVATE_UPLOAD_DIR` must NOT be reachable through any Nginx location — private attachments are read only via the identity-gated `GET /api/media/verification/[filename]`, which the proxy forwards to Next.js under `/api/`.
